# v0.3.0：每一条都有了自己的 ID

这一版改了日记数据的组织方式：**每个周目标、每件「这周的事」、每条日记，都有了一个固定的 ID**。多台设备同步时，靠它认出「这是同一条」，改了字也认得出来。

## 主要变化：条目 ID

### 为什么要改

以前同步合并靠**内容**认条目。改一个字，就等于「删掉旧的一条、加上新的一条」。两台设备同时动了同一条时，程序只能猜：新的这条正好挨在旧条目原来的位置，大概就是同一条。猜不准的时候，一边的改动会丢，或者多出一条。

现在每一条在 `.md` 文件里行尾带一个 ID：

```markdown
## 周目标
- [ ] 投三份简历 ^k3f9a2

## 这周的事
### 周一
- 跑完计算 ^b81zte

## 日记
### 10-18 周日
- 11:57 开始画手帐 ^r7n2kq
```

合并时按 ID 对上同一条，再逐项比较：文字、勾选、周几、时间、缩进。哪边改了哪项，就用哪边的。

### 用起来有什么不同

| 两台设备同时…… | 以前 | 现在 |
|---|---|---|
| 一台改了某条的字，另一台勾选、挪了位置、改了周几或时间 | 被当成两条不相干的条目，其中一边的改动会丢 | 两样都保留 |
| 一台删了某条，另一台改了它 | 改了的留下（靠猜） | 改了的留下（确定） |
| 把同一条改成了不同的字 | 靠位置猜是不是同一条 | 确定是同一条：后同步的那台为准，会提示被替换的是哪一条，被替换的那一版存进「历史版本」 |
| 把某条挪到了别的周几 | 当成删了一条、加了一条 | 认得出是同一条 |

### 对 `.md` 文件的影响

- 行尾的 `^k3f9a2` 用的是 Obsidian 块 ID 的写法。在 Obsidian 里可以用 `[[2026-W42#^k3f9a2]]` 引用某一条。
- **旧文件不用转换。** 没有 ID 的条目，按内容算出一个固定的 ID，每台设备算出来都一样；这一周下次保存时写进文件。
- 在编辑器里手写新条目时不用加 ID，页面会补上。改字的时候别动它。
- 在编辑器里复制一行，会连 ID 一起复制。读进来时，重复的那个会自动换一个新 ID。
- 多行的日记条目，ID 写在最后一行末尾。

### 局限

两台设备都是旧版本写的、还没有 ID 的条目，如果被同时改成不同的字，仍然认不出是同一条。这时两版都留下，不会丢，但会多出一条。新版本保存一次之后，这些条目就有 ID 了。

### 升级建议

- **所有设备都升级。** 旧版 App（0.2.x）能照常同步，数据不会丢，但它会把行尾的 `^xxxxxx` 当成文字显示出来。
- 网页版已经更新。

## 其他改动

### 能反悔了：历史版本和同步记录

- **历史版本**（周页面底部）：本机某一周的内容被同步、合并、文件夹读回、导入或恢复换掉之前，会先存一份快照；自己编辑时，每 10 分钟最多存一份。可以预览，也可以一键恢复；恢复算一次编辑，会同步到其他设备。快照只存在这台设备上，每周保留最近 30 份。
- **同步记录**（同步面板里）：上传、下载、合并、出错都记下来，最多 200 条。同一条被两边改了时，被替换的是哪一条也写在这里。

### 同步更可靠

- 同步状态如实显示：有没上传的改动时，显示「N 周待上传」，不会再显示绿色的「已同步」；离线时显示「离线 · N 周待上传」。
- 合并本身出错时，本地内容原样保留，这一周报错，其他周照常同步。以前会悄悄整份换成服务器上的版本。
- 每个请求最多等 15 秒。弱网下不会一直卡在「同步中」。
- 切到后台或关掉页面时，刚打的字立刻存进本机，并推送一次。
- 同一条被两边改了的提醒会一直留着，直到点开同步面板看过。

### 网页版整版更新

网页版的页面文件现在整版缓存、整版更新，不会再出现新旧文件混着用。新版本在后台装好后，在你没打字的时候自动刷新，或者在底部提示「有新版本，点这里刷新」。（安卓 App 的页面文件打包在 APK 里，不受影响。）
