## 图片

### 数据
- **本机**：IndexedDB 库 `myweek-img`，对象仓库 `i`。每张图两条：`ID`（大图，长边 ≤ 1600，JPEG 0.82）和 `ID` + `t`（缩略图，长边 320，JPEG 0.7）。
- **ID**：`"i" + Date.now().toString(36) + 3 位随机`。前 8 位是时间，清理缓存时用它判断「是不是一天以内新加的」。
- **周文件**：条目的续行 `![](img:ID)`，一张一行，ID 在最后一行末尾（和条目 ID 的规则一样）。内存里是 `entry.img = "id1,id2"`（字符串而不是数组，因为 `merge.js` 用 `===` 比字段；创建条目的地方都要写 `img: ""`，否则两边一个 `undefined` 一个 `""` 会被当成冲突）。
- **队列**：localStorage `myweek-imgq` = `{ up: [ID], del: [ID] }`。

### 流程
- **加图**：`addPicked(files, target)`（target 是条目 ID，`null` 表示输入框）。先放一个 `loading` 占位（调暗预览 + 「解码中」），再一张张 `Img.add`。成功后，输入框的进 `pend`，条目的写进 `entry.img` 并保存。
- **解码**：`createImageBitmap(file, {imageOrientation: "from-image"})` → 不带选项 → `<img>.decode()`，三级兜底。**只解码一次**，大图和缩略图都从同一个位图画出来；整个过程失败最多重试 3 次。
- **上传**：`Img.add` 成功就进 `up` 队列。`Sync.run()` 最后调 `Img.sync(imageApi)`：先处理 `del`（两个键都删），再处理 `up`（先传缩略图再传大图）。网络错误直接抛，队列留着下轮；413 / 415 丢弃并提示；507（总量满）保留并提示，不再试后面的。
- **下载**：`Img.url(id, thumb)` 本机没有且开了同步，就 `Sync.fetchImage(key)`，存进 IndexedDB 再返回。服务器 404 返回 `null`；网络错误抛错，**不缓存失败结果**，下次渲染再试。
- **删除**：`Img.remove(id)`：本机两个键立刻删，从 `up` 去掉，加进 `del`，排一轮同步。入口有三个：条目缩略图的 ×、大图的「删除这张」、输入框待记图的 ×（解码中被取消的，加完之后补一次删）。
- **清缓存**：同步结束、且没有待推送的周时，`Img.prune(referencedImages())`：删掉本机没人引用的图（别的设备删掉的）。例外：还在 `up` 里的、ID 里时间在一天以内的。服务器上的不动。

### 服务器
- 存在账号目录的 `images/ID`，二进制，无扩展名。ID 只允许 `[A-Za-z0-9-]{4,48}`。
- PUT：先认证；不合法 ID / 超 `MAX_IMAGE` 时**先把请求体读完再回错误**（否则客户端还在发送时连接被关，看到的是 `ECONNRESET` 而不是 413，队列会一直重试）；开了加密的账号只收 `MYWEEK-E2EE/1 ` 开头的密文，没开的收 JPEG 或密文；总量超 `IMAGE_QUOTA` 回 507；先写 `.tmp` 再 `os.replace`。
- GET：`Cache-Control: private, no-store`。删了就是删了，不能留一份在浏览器 HTTP 缓存里。
- DELETE：直接 `unlink`，不存在也回 200（可重复）。不进 `.history`，没有回收站。
- 不做服务器端自动清理孤儿图（见「没做的」）。

### 加密
图片的格式是文本头 `MYWEEK-E2EE/1 <指纹>\n` + `IV(12) || 密文`（原始字节）。AES-GCM，附加认证数据是图片的键（`ID` 或 `ID`+`t`），所以服务器把 A 图的密文挪成 B 图会解不开。是否加密看服务器 `/api/meta`（`acct.e2ee`），上传发生在 `checkAccount()` 之后，不会拿到过期状态；下载是看数据开头有没有魔数。

## 英文界面
- **规则**：代码里写 `tr("中文原文", 参数…)`，中文就是键，`{0}` `{1}` 是参数；`EN` 里没有对应的就原样显示中文，不会出现空白。页面里写死的文字不用改代码，`trDom(document.body)` 启动时按整句替换（文字节点、`placeholder`、`title`、`aria-label`、`alt`）。
- **星期 / 日期**：`dayName(i)`、`dayShort(i)`、`monthDay(d)`（`dates.js`）。**不要**在界面上直接拼 `"周" + WD[i]`；`markdown.js` 里的 `WD` 是文件格式，永远是中文。
- **数量**：`cnt(n)`（「3 条」 / "3 entries" / "1 entry"）和 `cntShort(n)`（周页格子里的）。
- **文件格式不翻译**：`## 周目标` 这些标题永远是中文，换语言不能改数据。
- **判断语言**：`navigator.languages[0]` 以 `zh` 开头是中文，其余英文；`?lang=zh|en` 临时指定。
- **测试**：`tests/i18n.test.js` 扫所有 `tr("…")` 和 `index.html` 里的中文，缺英文、`{0}` 对不上、`EN` 里有没人用的条目都会失败。**加了界面文字要在 `i18n-en.js` 补一条。**
- **坑**：键里的 `\n` 要和代码里的写法一模一样；新增 / 改 `tr()` 的第一个参数后，别忘了在 `EN` 里同步改。`cnt` 是全局函数，局部变量不要再叫 `cnt`（周页折叠那里踩过一次，已改成 `num`）。

## 新功能弹窗
- `whatsnew.js` 的 `NOTES` 是 `[{version, items:[tr(…)]}]`，新的放最前面。localStorage `myweek-seen-version` 记「上次看到哪一版」。
- 弹不弹：全新安装（没有任何本地数据、没开同步）只记版本号不弹；有数据但没有这个记录（从没有这个功能的老版本升级）会弹；`seen < 当前版本` 就把中间所有版本的说明一起弹（新的在前）。
- 点「知道了」/ ✕ / 返回键关掉才算看过。这一版没有写说明就不弹，并静默记下版本号。
- 弹窗开着时压一条历史记录，安卓返回键先关它。`popstate` 里统一处理：有任何打开的 `<dialog>` 就关掉并返回。
- **发新版时**：在 `NOTES` 最前面加一条 + 在 `i18n-en.js` 补英文 + 写 `docs/releases/vX.Y.Z.md`。

## 安卓返回键
- 进日记页 `pushState({day:1})`；返回时（页面里的「‹ 这一周」或系统返回键）统一走 `history.back()`，`popstate` 里切视图。直接用 `#d日期` 打开日记页时，先补一层 `#week` 再压日记页，返回也先回周页。
- **原生这一半**（`MainActivity.java`）：Capacitor 8 在没装 `@capacitor/app` 插件时**不处理返回键**，Activity 默认直接退出，网页再怎么压历史也没用（0.4.0 第一版就是这个坑：电脑浏览器里好好的，真机上返回键还是「大退」）。所以在 `MainActivity` 里加了一个 `OnBackPressedCallback`：`WebView.canGoBack()` 就 `goBack()`（pushState 压的条目也算），否则关掉回调、交给系统默认处理，也就是退出。没装 `@capacitor/app`，是因为这几行原生代码就够了，不用多一个依赖。
- 大图和新功能弹窗也各压一条（`{img:1}` / `{dlg:1}`）。

## 安卓状态栏跟着亮暗切换
- **现象**：手机在亮色 / 暗色之间多切几次，顶部状态栏（时间、电量那一行）的图标颜色和底色会跟不上，浅色底配浅色图标，看不清。
- **原因**：`AndroidManifest.xml` 里 `MainActivity` 声明了 `uiMode`（自己处理亮暗切换），所以切换时 Activity **不会重建**，`styles.xml` / `values-night/styles.xml` 里写死的 `windowLightStatusBar` 只在启动时读一次，之后不再更新；另外 `capacitor.config.json` 的 `backgroundColor` 是固定的浅色 `#f3f5f7`，WebView 和窗口的底色也一直是浅色。网页里的 `<meta name="theme-color">` 对 App 里的 WebView 不起作用。
- **做法**（`MainActivity.java`）：`applySystemBars()` 按当前是不是夜间模式，用 `WindowInsetsControllerCompat` 设状态栏 / 导航栏图标深浅，并把窗口和 WebView 的底色设成 `#f3f5f7` / `#161a22`（和网页 `theme-color` 一致）。在 `onCreate`、`onConfigurationChanged`（系统切换时）、`onResume`（后台时系统换了模式，回来补一次）三处调用。Android 15 以下还要多设 `setStatusBarColor` / `setNavigationBarColor`。
- 这是根据原因推断的修法，**要在真机上反复切换亮暗几次确认**；改页面底色时，记得把 `LIGHT_BG` / `DARK_BG` 和 `style.css` 里的 `--paper` 对上。

## 发版清单（0.4.0 这次的顺序）
1. `package.json`、`package-lock.json`（两处）、`web/js/version.js` 三处版本号一致（`tests/updates.test.js` 会查）。
2. `NOTES` 加一条，`i18n-en.js` 补英文，`docs/releases/vX.Y.Z.md` 写好。
3. `npm test` 全过。
4. **先部署服务器**（`./config/deploy.sh`），再发 App：旧服务器没有图片接口，新 App 每轮同步会提示「图片没能同步」。
5. 打标签 `git tag vX.Y.Z && git push --tags`，Actions 构建签名版发到 Releases；再用 `config/publish-apk.sh` 发 Gitee。
6. **真机**上装好后试：加图、同步、另一台设备看图、删图（另一台应显示「图片看不到…」）、**返回键（日记页 → 周页面 → 退出；大图和弹窗开着时先关它们）**、切系统语言。返回键、图片选择这类原生行为在电脑浏览器里测不出来，一定要在真机上过一遍。

### versionCode 的坑（已改）
安卓不允许版本号变小。以前 CI 用 `run_number` 当 versionCode；本机为了试包用过 9–13，如果手机上装着 13 的测试包，CI 出的 v0.4.0（run 9）就装不上。后来改成 `run_number + 100`，但这又有问题：手机上装着正式包 110 时，本机测试包只能用 1–99，装不上（「无法降级安装」）。**最终方案：CI 用 `run_number × 10 + 100`**（v0.4.0 = 109、v0.4.1 = 110 已发出，从 run 11 起是 210、220、230…）。两次正式发布之间有 9 个空位，**本机测试包用「手机上现在装的正式包 + 1…+9」**（比如装着 110 就用 111–119），下一个正式包一定比它们大，两头都不会降级。

## 本机出 APK（Windows）
不用等 Actions，也能出正式签名的包（用 `config/android/` 里的同一把签名）。需要：JDK 21、Android SDK（平台 36、build-tools 36.0.0）、Gradle 8.14.3 的压缩包。流程：`npx cap sync android` → 设置 `JAVA_HOME`、`ANDROID_HOME`、签名的四个环境变量、`VERSION_CODE`（1–99）、`VERSION_NAME` → `android/gradlew assembleRelease`，产物在 `android/app/build/outputs/apk/release/`。再用 `apksigner verify` 验一下签名。

**踩过的坑**
- 开着 v2rayN（系统代理 `127.0.0.1:10808`）时，Gradle wrapper 自己下载 Gradle 会 SSL 中断。办法：用 `curl` 下好 zip，临时把 `android/gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl` 改成 `file:///…/gradle.zip`，构建完 `git checkout` 还原。Java 访问网络要加 `JAVA_TOOL_OPTIONS=-Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=10808`。
- Windows 上的 `python` 是应用商店的占位程序，跑不了；本机可用的是 miniforge 里的 python。
- 浏览器里预览改了的页面，要先注销 service worker、清缓存，否则看到的是旧版本。
- 部署时 Docker 会打印 `IPv4 forwarding is disabled`，不影响这个服务（容器是 `healthy`）。

## v0.4.1（小版本补丁）
- **日记条目删除**：`bullet()` 里加 `xButton`，`deleteEntry(id)` 删这一条和它后面缩进更深的子条目（列表是按显示顺序排的，往后数到缩进不比它深为止），里面的图片逐张 `Img.remove`。叉叉在 `.b:focus-within` 时才显示（和 `.wrow.editing` 同一个思路：点进去编辑才出现），绝对定位在右上角，编辑时给 `.tx` 右边留 28px。
- **加图失败不再消失**：`loading` 里的任务失败后带 `failed`（原因），留在原地显示「没加上」，用户点 × 才去掉；`decoding(j)` 判断「还在解码」，只有这种才挡「记」。解码全局排队（`decodeChain`），一次一张。`Img.add` 里三种解码都失败（`e.ours`）的只多试一次。
- **多图换行**：`.th` 的 `flex-basis: clamp(64px, calc((100% - 16px) / 3), 96px)` + `aspect-ratio: 1`，窄屏一行至少 3 张，宽屏最大 96px。
- **「一张能上、后面全挂」（真机上复现了，0.4.2 修）**：手机上一次选几张图，只有第一张成功，其余都报「解不开（image/jpeg）」，换小图、换格式都一样，所以不是图片本身的问题。原因是**选完以后，排在后面的文件等到轮到它们解码时已经读不了了**（安卓上选出来的文件是临时授权的，只在刚选完的一小会儿稳定可读；第一张是立刻开始读的，所以总能成功）。修法：`addPicked` 一开始就对每个文件调 `file.arrayBuffer()` 读进内存（`readNow`），之后都从内存副本解码；选择框的 `value` 也等全部读完才清空（`afterRead`）。读失败时错误是「读不了这个文件…请重新选一次」。电脑浏览器里没有这个问题，所以之前怎么试都复现不了。
- **「3 张只留 1 张」（最早的报告，现在看就是上面这个）**：电脑浏览器里各种选法（一次选 3 张、连续选 3 次、大图、开着同步）都是 3 张。猜测是失败的图只在底部状态栏提示、被漏看；加了上面的可见失败提示。如果还有人遇到，看失败格子的提示和控制台里的 `[图片]` 日志。
- **新功能弹窗没加 0.4.1 的说明**（有意的）：`NOTES` 里只有 0.4.0。看过 0.4.0 的人升到 0.4.1 不弹；直接从 0.3.x 升上来的还是弹 0.4.0 的。`tests/whatsnew.test.js` 有一条覆盖。

## 没做的 / 已知限制
- **孤儿图**：服务器上没人引用的图（比如上传到一半取消、周文件被恢复成没有引用的旧版本）不会自动清理。做自动清理有风险：新设备还没同步完时，会把别人的图当成孤儿删掉。想做的话，先加手动「清理未使用的图片」，且只清理超过几天的。
- **HEIC / AVIF**：解不开就报错，没加转换库（要几百 KB）。
- **导出 / 导入**：`.md` 里只有引用，不带图片。
- **回收站**：删了就没了，没有「最近删除」。从历史版本恢复到含有已删图片的版本，会显示「图片看不到」。
- **一天以内的缓存不清理**：在另一台设备上删掉的图，本机缓存最多多留一天。
- **粘贴只在日记页生效**；手机上没有粘贴入口（要用图片图标）。
- 单张最大 4 MB、总量 500 MB 是拍脑袋定的，可以用 `MAX_IMAGE`、`IMAGE_QUOTA` 调。
